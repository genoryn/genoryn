# GENORYN 1.2.0

A wallet security update for **Mainnet 1.0**: the 24-word recovery phrase is shown again only
to someone who types the wallet password, it is kept off the screen otherwise, and new wallet
files are four times more expensive to attack. No consensus rule changes: the genesis block,
chain id, block history, supply cap, emission schedule, RandomX, difficulty rules, Orchard/Halo 2
validity, serialization, coinbase rules and the P2P protocol are exactly those of 1.0 and 1.1.

## Recovery phrase, only with the password

- Settings → **Wallet security** → *Show recovery phrase* asks for the wallet password again
  every time; the session's stored password is never used. The wallet CLI decrypts the phrase
  from the file for that one request (`reveal_phrase`) and answers only to the right password.
- The 24 words appear in a numbered grid, masked until asked for, as non-selectable text: no
  copy button, nothing to select, nothing on the clipboard.
- They are wiped after 60 seconds, when the window loses focus or is minimized, on close, on
  lock and on the inactivity lock. After 3 wrong passwords each attempt waits longer (30 s,
  doubling up to 10 minutes).
- *Check my backup* asks for three random words from your paper copy and records the backup
  confirmation shown on the Privacy & Security page.
- The phrase shown after creating a wallet uses the same non-copyable grid.

## Kept out of screen captures

- While recovery words are on screen (a new wallet's, revealed ones, or words being typed into
  Restore) the window is excluded from screenshots, screen recording, screen sharing and
  remote-desktop capture on Windows 10 2004 and later, and shown black on earlier Windows.
- Linux has no such switch for applications; the window says so instead of claiming
  protection.
- The one system call is in a new small crate, `genoryn-screen-guard`; the wallet application
  keeps `#![forbid(unsafe_code)]`.

## Stronger wallet files

- New wallet files are **version 2**: Argon2id with **256 MiB** (version 1: 64 MiB), 3 passes,
  XChaCha20-Poly1305. The cost parameters are stored in the file and authenticated with it, so
  lowering them makes decryption fail, and files asking for unreasonable parameters are refused.
- Version 1 files open exactly as before; nothing is rewritten automatically.
- *Change password* (*Strengthen file / change password* for a version 1 file) re-encrypts the
  file under a new password or the same one: the new file is written beside the old one, opened
  again and compared, and only then replaces it. A wrong current password, or any failure, leaves
  the original byte for byte unchanged.
- Opening a wallet takes about 0.5 s on a current PC (key derivation).
- **Compatibility:** wallets created or re-encrypted with 1.2 cannot be opened by 1.1 or earlier
  ("unsupported wallet storage version"); their 24 words restore them in any version.

## Stronger new passwords

- New and changed passwords need at least 12 characters (was 10) and a strength estimate of at
  least 50 bits, with a meter while typing. Repeats, runs and very common words count for
  little. Existing passwords keep working.

## Command line

- `genoryn-wallet-cli protection`, `recovery-phrase` and `change-password`; JSON ops
  `wallet_protection`, `reveal_phrase`, `change_password`.

## Not protected against

Malware already running on the computer (keyloggers, memory or screen readers by other means), a
camera or a person watching, a guessable password, and anyone who finds the paper copy. See
[recovery phrase and wallet file](../wallet/recovery-and-wallet-file.md).
