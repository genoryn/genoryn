# GENORYN 1.1.0

A wallet, node, miner and tooling update for **Mainnet 1.0**. No consensus rule changes: the
genesis block, chain id, block history, supply cap, emission schedule, RandomX, difficulty
rules, Orchard/Halo 2 validity, canonical serialization, coinbase rules and the P2P protocol
are exactly those of 1.0. Existing wallets, recovery phrases, scan caches, outboxes, mining
histories and balances are read unchanged; new local files (`.chainstate`, `.references`) are
additions that 1.0.x ignores.

## Shared mining (PPLNS)

- New open-source pool service **`genoryn-pool`** (`serve`, `account`, `payout`, `status`,
  `bench`) and **`genoryn-miner --pool tcp://… | tls://…`** (optionally through Tor with
  `--pool-proxy socks5h://…`). Solo mining is unchanged.
- Every share is hashed again with real RandomX (light or `--fast-verify` full-memory) and
  credited exactly its share difficulty; VarDiff never changes the value of equivalent work;
  duplicate, stale, out-of-range and low-difficulty shares are refused; per-session nonce ranges.
- Exact integer PPLNS: credits in 2^-32 gori, credits + dust + fee equal the coinbase exactly;
  nothing is credited before 60 confirmations; orphaned blocks never pay; reorganizations after
  maturity are reversed from unpaid balances with any shortfall recorded as operator deficit.
- Durable ledger on SQLite or PostgreSQL (serializable, retried), set-based hot paths; shares
  are acknowledged only after they are committed; restart keeps every number.
- Payouts: batches of up to 15 recipients through the wallet CLI's new `send_many`, paid at most
  once per batch reference; confirmed only when the wallet sees the transaction in a block.
- Activation: the requested mainnet height **1150 had already passed** when this release was
  prepared (observed tips 1136 → 1293 on 2026-10-11); a new mainnet pool refuses to start until a
  future height is confirmed explicitly. Nothing is backdated.
- Measured on one machine: 1,982 shares/s full-memory verification (≈29,700 miners at 15 s
  shares); 100,000 simulated sessions on one gateway (99,856 served); ledger accounting for
  1,000,000 simulated miners. See [shared mining](../mining/shared-mining.md).

## Verified Payment Proof 2.0

- New payments commit a payment-specific Ed25519 key in the last 40 bytes of the encrypted memo
  (text up to 471 bytes; older wallets do not see it). The key is derived from the seed, the
  payment's own spent nullifier, recipient, amount and position — recoverable from the 24 words,
  not derivable from viewing or receiving keys.
- Verify payment: optional amount check; distinct outcomes for verified, recipient or amount
  mismatch, pending, reorganized, unavailable and legacy payments; advanced details.
- **Request sender verification** (`GNRCHAL1-…`, fresh nonce, one hour) and **Answer payment
  challenge** (`GNRRESP1-…`, Ed25519 signature). Replays, impostors, the recipient's own keys and
  any other payment, recipient, amount or network fail.
- Wallet CLI: `create_payment_challenge`, `answer_payment_challenge`, `verify_payment_challenge`;
  `verify_proof` adds `outcome`, `sender_evidence`, `reorg_risk`, `amount_matches`.
- `GNRPROOF1` codes, JSON and PDF proofs remain valid. See [Payment Proof 2.0](../wallet/payment-proof-2.md).

## My Full Node

- Network → **My Full Node** with **Start My Full Node**, Stop, Restart, Open Node Folder, View
  Node Logs, Node Settings, Connection Diagnostics; preflight checks (platform, disk, memory,
  program, data folder, RPC port, existing node); honest status and synchronization labels.
- Optional and off by default: keep the node running after the wallet closes (recorded process
  id, stoppable later); start it when you sign in (per-user entry, no service, no ports).

## Faster, resumable synchronization

- Nodes serve up to 32 blocks per `v1/blocks` request; wallets page through 1.0 nodes too.
- Full mode with your own node keeps its sealed verified chain and a version-bound state
  snapshot: repeated sends and proofs at mainnet height 1238 take 0.40 s instead of 11.29 s.
- Quick mode checks RandomX work and Halo 2 proofs of long downloads in parallel before applying
  every rule in order: the real 1,212-block chain validates in 18.0 s instead of 49.0 s, with an
  identical final state.
- One commitment-tree root per block instead of two (stored replay 9.5 s → 5.9 s); first scans
  are checkpointed every 2,000 blocks.

## Privacy & Security

- Wallet → **Privacy & Security**: Verified / Warning / Failed / Not tested per check, with its
  basis; settings and your own statements are shown as such. Controlled loopback-only tests
  (proxy fails closed, socks5h only, Tor-only keeps RPC local), node-reported Tor and connection
  evidence, wallet file encryption and GENORYN-folder hygiene, backup checklist, update status
  and the limits of checksum-only releases. No anonymity score; nothing uploaded.

## Verification and CI

- Fixed the baseline CI failures: the devnet lab's SOCKS stand-in now really stops listening on
  Linux (`stale, never zero`); the Windows native-controls test clicks controls where the wallet
  reports drawing them (`--layout-report`) and unlocks with the keyboard; the fuzz workspace lock
  follows the workspace version; compiled dependencies are cached before the practical suite.
- New: a real-chain Payment Proof 2.0 test (RandomX blocks, Halo 2 proofs, 10 GNR Alice → Bob);
  a devnet CLI check of the challenge flow; a real devnet pool lab (weak and strong miners,
  hostile shares, maturity, audit, restart, idempotent payout received exactly); pool ledger
  tests on SQLite and on a PostgreSQL 17 CI service; storage-hygiene and security-check tests.

## Not in this release

- No independent audit. No code signing or reproducible-build attestation.
- No native P2Pool (it needs multiple coinbase outputs: a consensus change).
- `genoryn-pool` does not terminate TLS itself; put public pools behind a TLS terminator or an
  onion service.
- Node initial block download is still validated one block at a time on the P2P path; the
  parallel pre-verification applies to wallet validation.
- No 1.1.0 binaries are published by this change: packages are built by the manual release
  workflow after approval.
