**Mainnet release. The software has not been independently audited: mine or hold only what you can afford to lose.**

GENORYN 0.6.0 builds Tor into the node and the wallet. A Tor mode needs nothing else
installed, new installations hide their IP address from peers from the first start, and
the wallet can now run as a **light wallet** without a node of its own.

### Tor is built in

- Hybrid and Tor-only modes use a Tor client inside GENORYN
  ([Arti](https://gitlab.torproject.org/tpo/core/arti)). Nothing to download or keep
  open; Tor Browser or a Tor daemon you already run still works (**My own Tor**).
- **New installations start in Tor only**: every peer connection, peer lookup and
  payment broadcast goes through Tor, and nothing falls back to a direct connection.
- **Existing installations keep their mode.** Upgrading never switches anyone to Tor
  silently; choose **Network → Network privacy → Tor only** to switch.
- An optional onion service lets other nodes connect to yours without learning your IP.
- Tor directory information (about 10 MB) is downloaded on the first start, so the first
  connection takes a little longer.

### Payments always get out

- A payment created while Tor or the network is down waits and goes out when a peer is
  reachable again; it is kept on disk, so it also survives a restart. In Tor-only mode
  it never goes out any other way.
- A peer that silently drops your payment can no longer stop it from spreading.
- Payments are first sent to one peer and only then more widely, which makes it harder
  to tell which computer created them. This is not anonymity.

### Light wallet

**Network → Light wallet** turns the wallet into one without a node of its own: it reads
the chain from remote nodes you list and sends payments through them, only over Tor.
Every block is fully validated on your computer; the remote nodes never see your
addresses or balance. Use two or more independent nodes. Usernames and mining still need
a node of your own. Node operators offer this with `--public-rpc --onion-service`.

### Important for the first weeks

Tor-only nodes need bootstrap peers that Tor can reach. When this release was made, the
mainnet seeds did not accept connections from Tor yet. Until their onion addresses are
published (`seeds/mainnet-onion.txt`, read automatically at startup, no new release
needed), a new Tor-only installation may show "no peer could be reached through Tor"
and stay at height 0. Meanwhile you can add an onion peer you know, or choose
**Hybrid** on the Network page.

### Under the hood

- A Windows-only freeze of the built-in Tor client (a time-limit search in one of its
  dependencies that never ended on Windows) is fixed with a small, recorded patch.
- Status shows Tor progress, readiness, onion address and clear warnings; stale errors
  disappear when Tor recovers, and peers are retried at once.
- New public RPC endpoint `POST /v1/relay` for light wallets.
- Peer protocol, consensus, monetary rules and wallet files are unchanged: 0.6.0 works
  with 0.4.x and 0.5.x nodes, and opens their chain data and wallets.

### Upgrading

Run `GENORYN-Setup-0.6.0.exe` (or the Lite installer) over your current installation;
wallets and chain data are kept.

GENORYN is not code-signed yet. If Windows 11's Smart App Control is on, the installer
explains how to turn it off. SmartScreen's "Windows protected your PC" prompt: choose
**More info → Run anyway**.

### Verify before running

Every installer and archive has a matching `.sha256` file; each package contains
`SHA256SUMS` and `release-manifest.json` with the exact source commit and edition.
Packages are **unsigned builds**.
