Contribute

Nobody owns it. Anyone can improve it.

Genoryn Krypton is open source under MIT or Apache-2.0. There is no company behind it and no team to apply to: changes are proposed in public and judged on what they do. You do not need to be a programmer to help.

The full-node guide
Code

Build it, test it, send a change

Everything is written in Rust and lives in one repository: github.com/genoryn/genoryn. You need Rust 1.89 or newer and no other toolchain.

git clone https://github.com/genoryn/genoryn
cd genoryn
cargo build --release                                   # node, miner, wallets
cargo test --workspace                                  # all tests
cargo fmt --all -- --check                              # formatting
cargo clippy --workspace --all-targets -- -D warnings   # lints
python website/build.py                                 # this website, into website/dist

Try your change on a private network of your own before you propose it. Never test against other people's funds or nodes:

kryptond --network devnet --no-seeds

A good pull request

  • One change, with a few sentences on what it does and why.
  • Tests for the behaviour it changes. Consensus, proof and wallet code is not merged without them.
  • The four commands above pass. They run again on Linux, Windows and macOS when you open the request.
  • Plain words in comments and documents, no unsafe code in networking, no new dependency without a reason.
  • A change to the rules of the network needs an update of the specification in docs/spec and a block height at which it starts, announced in advance. Never an immediate switch: people's nodes must have time to update, and nobody's coins may be stranded.

The full guide is CONTRIBUTING.md. By contributing you agree that your work is licensed like the rest of the project, under MIT or Apache-2.0 at the user's choice.

Review

Where careful eyes are worth most

The software has extensive automated tests and an internal review, and no independent audit yet. If you know cryptography, consensus or Rust, these are the places where a mistake would cost the most:

The spend proofThe circuit that proves a transfer valid, and its zero-knowledge masking: crates/krypton-zk, docs/spec/spend-circuit.md
Consensus and reorganizationscrates/krypton-core/src/consensus.rs, crates/krypton-store
The light wallet's verificationcrates/krypton-light
Keys and the wallet filecrates/krypton-wallet-core
The handshake between nodescrates/krypton-p2p/src/session.rs

If you find something an attacker could use, report it privately.

Documentation

Make it clearer for the next person

Documentation is part of the software: a rule nobody can understand is a rule nobody can check. It lives in three places, all in the repository, all plain text you can edit in a browser on GitHub:

This website

The folder website: one HTML file per page, no framework. python website/build.py builds it. The list of updates comes from website/updates.py.

The README

README.md is the whole project on one page, for people who read on GitHub.

The specifications

docs/spec says exactly what the rules are: the spend circuit, consensus, rewards, the light client, addresses and the network, atomic swaps.

What helps

  • Say where you got lost. Open an issue: "the page on swaps does not say what happens if I close the wallet". That alone is a contribution.
  • Fix what is wrong or out of date. A number that changed, a button that was renamed, a step that no longer exists.
  • Write it the way you would say it. Short sentences, ordinary words, what happens and what to do. No promises about price, ever: the project makes none.
  • Check it. Run the command you describe. Documentation that is confidently wrong is worse than none.
Translations

Where they stand

This website and the wallet speak ten languages: English, German, French, Spanish, Portuguese, Russian, Turkish, Simplified Chinese, Japanese and Korean. English is written by the project; the other nine are machine translations that no person has checked yet. They are marked as such at the bottom of every page.

A wallet's words are instructions about money, so this is where help matters most:

  1. Read a page in your language

    If a sentence is wrong, unclear or sounds unnatural, open an issue with the page and the sentence, or fix it yourself.

  2. Fix it in the catalog

    Every language is a set of files in website/locales and apps/krypton-wallet/locales. The translation guide explains them, and the glossary keeps words like recovery phrase and refund the same throughout. A checker catches broken links and markup before anything is merged.

  3. Keep it current

    When the English changes, its translations are shown in English until someone translates the new text. A language with people who keep it current can lose the machine-translation mark.

A language that is not here yet can be added the same way: start with the guide and open a pull request.

Start small

Report one thing that confused you, or fix one sentence. That is how every contributor started.
