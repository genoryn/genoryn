Network support

A network is the people who run it.

Genoryn Krypton has no servers of its own to rely on. It is the computers of the people who run the software, passing blocks and transactions to each other. Every full node you add makes that web denser, and a denser web is harder to split, to censor and to lie to.

What your node does

Four jobs, done without asking

It carries

New blocks, transactions and mining shares reach your node from some peers and leave it for others, after it has checked them. Invalid data stops at your node: it is never passed on.

It serves

A node that is new, or was switched off for a week, gets the blocks it lacks from nodes that have them. If yours accepts incoming connections, it is one of them.

It introduces

Nodes find each other by asking peers for addresses of other nodes. Each honest node in that address book makes it harder to surround a newcomer with dishonest ones.

It refuses

A peer that sends a malformed message, an invalid block or transaction, or shares without work is disconnected and its address refused for 24 hours. Bad data finds fewer and fewer doors.

Incoming connections

Listening is what helps most

Every node connects out to up to 8 others. A node that also accepts connections, up to 64, is where those outgoing connections land. Without enough listening nodes, new nodes have nobody to connect to.

The node the wallet starts does not listen unless you tell it to: nothing on the internet can then open a connection to your computer. That is the right default for a laptop. If your computer is on most of the time and your connection has room, switch it on:

  1. Let nodes in

    In the wallet: Network → Let other nodes connect to my full node, then restart the node. On a server, kryptond listens by default on port 30333.

  2. Open the door

    On a home connection, tell your router to forward TCP port 30333 to the computer that runs the node, and allow it through that computer's firewall. The full-node guide shows how.

  3. See that it works

    After a while, getpeerinfo in the wallet's console shows peers with "inbound": true.

Safety

Built so that peers cannot use your node against you

Encrypted linksEvery connection begins with an X25519 + ML-KEM-768 handshake and runs in ChaCha20-Poly1305 frames. Whoever records the traffic today cannot read it later with a quantum computer.
Nothing to break intoThe networking code is memory-safe Rust with no unsafe code. A peer can send protocol messages and nothing else: a node never runs commands, opens files or reaches its own API for a peer.
Strict limitsMessages of at most 8 MiB, with the length checked before memory is set aside; a cap on every list; 10 seconds for a handshake; at most 4 connections from one address; a cap on what is queued for a slow peer.
A careful address bookPeers can point your node only at public internet addresses, never at your own computer or your home network. No single part of the internet can fill more than 16 places in it.
An API for you aloneThe node's API listens on this computer only. It has no wallet and no administrative functions. To offer it to others, put it behind a web server with limits, as genoryn.io does.
What it costs you

Disk, a little memory, and bandwidth when others sync

A node keeps the whole chain, about 0.5 GB today, and uses well under a gigabyte of memory. Day to day it sends and receives one small block a minute. The larger cost is serving a node that is syncing from scratch: the whole chain, once, to each. You can bound all of it: fewer peers, no incoming connections, or simply switching the node off when you need the line. See Requirements and tuning.
