Security audits

Checked, fixed, and published.

Money is only as safe as the code behind it. Every part of Genoryn Krypton is reviewed again and again: the wallet, the swaps with bitcoin, the node, the rules of the chain, this website and the forum. Here is what each review checked, what it found, and how every finding was fixed.

26 November 2026 · 1.0.52 → 1.0.53

The whole system, reviewed again

Four reviewers, each in one area in depth: the swaps with bitcoin, the node and its network, the desktop wallet, and cryptography with the light client. Every finding was checked against the code; fixes that change what honest users see were tried on the real chain first.

  • No way to mint GNR beyond the schedule
  • No way to spend someone else's GNR
  • No way to break the privacy of transfers
  • No way to forge a block for a full node

What was checked

Four areas, each read line by line

Swaps with bitcoin

Every step of a swap and every way it can end: restarts at any moment, deadlines, refunds racing claims, fees in a busy Bitcoin network, and a counterparty or Bitcoin server that does not behave.

Node and network

The peer-to-peer layer under load from many addresses, the node's API and its limits, the offer board and the messages it relays, the files it keeps, and the server configuration.

The desktop wallet

What a web page, another program or another user of the computer could do with it, the password on every action that matters, updates, and everything the window shows from the network.

Cryptography and the light client

What a dishonest node can make a light wallet believe, key derivation and randomness, note encryption, and the decoding of everything that comes from the network.

What was fixed

Every finding, and what changed

The full report on GitHub has each finding with its fix and its test. In short:

AreaSeverityWhat was wrongWhat 1.0.53 does
Light walletCriticalA dishonest node could get a light wallet to accept blocks nobody had worked for, with payments in them.Every block above the release checkpoint is checked as a full node checks it, and the chain must pass through the checkpoint.
NodeCriticalOne peer could slow a node's handling of every other peer's messages.Peers' transactions are checked outside the message loop, a few at a time and within a budget.
Light walletHighA tiny payment could be made to show as a huge amount.Such notes are refused.
WalletHighWith the window's session token alone, a wallet could be added and made the one that receives payments and mining rewards.Adding a wallet needs the open wallet's password.
NodeHighBlock announcements, bare connections and relayed swap messages from one place could crowd out everyone else.Budgets per peer and client, room for new peers only after their handshake, and a daily quota of relayed message bytes.
ServerHighThe client address the node counts requests by came from a header only the firewall protected.It is taken from Cloudflare's header only when the request comes from Cloudflare.
SwapsHighA seller could reveal the secret with little time left, and a claim waiting in a busy mempool got more fee only once.The secret is revealed only with ten blocks left, and the claim is signed again every block with more fee.
WalletHighOn Linux and macOS, other users of the computer could read the window's session link.The wallet's folder and files are for their user alone, and the link is no longer printed.
Light walletHighThe work a node's tip claimed was remembered before its blocks were checked.Remembered only once every block up to it passed.
All areasMediumEleven issues: payment-proof confirmations, pending payments, note-tree data from nodes, board files, proofs of funds, mode and peer settings, a crashed wallet's link, the payment check of swaps, a finished seller's unclaimed GNR, unreadable swap records, and a deposit code that came before the lock.All fixed; each one is in the full report.
All areasLowFive smaller issues: response limits, frame protection, and arithmetic and checks with numbers from the other side of a swap.All fixed, the arithmetic covered by property tests.

Findings that are still being worked on are not described until they are fixed, so that nobody can use them first. The findings of the 1.0.52 audit are in its report.
