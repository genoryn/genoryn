What was checked

Six areas, each read line by line

The desktop wallet

Its local interface, the password on every payment, the 24-hour lock, the recovery phrase, the wallet file's encryption, the updater, the console, and everything the window shows from the network.

Swaps with bitcoin

Every step of a swap on both chains, what each side may do and when, the offer board, Quick Swap, and what happens when the other side, or the Bitcoin network, does not behave.

Bitcoin keys and signing

Where every Bitcoin key comes from and how much entropy it has, how deposits and withdrawals are built and signed, fees, the Bitcoin contract script, and how the secret of a swap is learned.

Node, network and updates

The node's API, mining jobs and payouts, the peer-to-peer layer, the installer and uninstaller, release signing and the update script for servers.

Consensus and cryptography

Every rule change since 1.0.2, the swap locks, the dormant token rules, the zk-STARK spend circuit, post-quantum note encryption and key derivation. All 93 consensus tests pass.

Website, forum and server

How this site shows data from the node, the download page, translations, the security headers, and Genoryn Talks: sign-in, sessions, names, posts and live chat.

What was fixed

Every finding, and what changed

The full report on GitHub has each finding with its fix and its test. In short:

AreaSeverityWhat was wrongWhat 1.0.52 does
SwapsCriticalA buyer's refund could be taken over by the seller's claim, and the buyer's wallet then counted the swap as refunded.It reads which transaction spent the contract. If it carries the secret, the wallet takes the GNR with it.
SwapsHighThe seller's wallet counted its bitcoin claim as done before it was in a block.Done only once it is in a block. A dropped claim is sent again, with a higher fee near the deadline.
SwapsHighThe secret was read from a claim in one exact layout only.It is found in any claim, checked against the hash lock.
WalletHighA hostile offer board could have placed script in the wallet window.Everything from the board is checked before the window sees it, and encoded for where it goes.
BitcoinMediumAmounts signed for Bitcoin payments came from the Bitcoin server's lists; a contract paid with a little more than agreed could not be claimed.Amounts are read from the real previous transactions, checked against their ids, and claims use the amount actually paid.
BitcoinMediumEvery Bitcoin payment spent all coins of the address, and the fee rate from the server was trusted up to 2,000 sat/vB.Only the coins a payment needs are spent, the fee is at most a tenth of what moves, and the fee rate is capped at 500 sat/vB.
WalletMediumThe nodes and the Bitcoin data source could be changed without the password.Both need the wallet's password. Real bitcoin trades only against mainnet GNR.
WalletMediumThe 24-hour lock could lock a wallet in the middle of a swap only it can finish.The lock waits while its coins are in a swap contract, seven days at most.
InstallerMediumUninstalling deleted everything in the chosen install folder.It removes only the files it installed, and the folder only if it is then empty.
ServersMediumThe node update script checked packages against checksums only.It checks the release signature with the key the install carries and never installs an older version.
WebsiteMediumThe download page had no hash to compare a download with.Each button shows its file's SHA-256 from the signed release checksums, checked when the site is built.
ForumMediumNames that only look like the administrator's or another member's were accepted.Names are compared as they look on screen.
All areasLowThirteen smaller issues (Low and Info): address checks, password attempt limits, more confirmations for large swaps, the installer's tools, forum sign-in and links, and others.All fixed; each one is in the full report.

Findings that are still being worked on are not described until they are fixed, so that nobody can use them first.
